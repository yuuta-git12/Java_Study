## 1. 参照型と基本型の値の変化

### 基本型(プリミティブ型)
メソッドに渡すと**値そのもののコピー**が渡される。呼び出し元には影響しない。

```java
static void change(int x) {
    x = 20; // コピーを書き換えているだけ
}
```

### 参照型
メソッドに渡すと**参照のコピー**が渡される。指している実体は同じなので、中身を書き換えると呼び出し元にも影響する。

```java
static void change(int[] x) {
    x[0] = 100; // 実体を書き換え → 呼び出し元にも反映される
}
```

ただし、参照そのものを差し替える(`x = new int[]{...}`)場合は、呼び出し元の変数には影響しない。

### Stringは特殊
`String`は参照型だがイミュータブル(不変)。中身を書き換えるメソッドが存在せず、変更するたびに新しいオブジェクトが作られるため、基本型のように振る舞う。

### まとめ表

| | 渡されるもの | メソッド内で値を変更 | 参照/変数自体を差し替え |
|---|---|---|---|
| 基本型 | 値そのもののコピー | 呼び出し元に影響なし | ― |
| 参照型 | 参照のコピー | 呼び出し元に影響あり(実体を書き換えた場合) | 呼び出し元に影響なし |

## 2. sealedクラスとオーバーライドの戻り値型

```java
sealed class Super permits Sub {
    double execute(double value){ return value * 1.25; }
}

final class Sub extends Super {
    int execute(double value){ return (int)(value * 1.1);} // コンパイルエラー
    double execute(double v1, double v2){ return v1 * v2; } // OK(オーバーロード)
}
```

### なぜエラーになるか
- 引数の型が親と完全一致 → **オーバーライド**とみなされる
- オーバーライドの戻り値型は「親と同じ」か「親のサブタイプ(共変戻り値型)」である必要がある
- `int`は`double`のサブタイプではない(暗黙変換できても型階層としてのサブタイプ関係にはならない)
- → コンパイルエラー

引数の**数**が違う場合はオーバーロードとして成立し、戻り値型は自由。

## 3. sealedクラスとpermits句

- **別ファイル**の場合は`permits`が必須(省略するとコンパイルエラー)

## 4. 独自例外クラスとgetMessage()

### 方法1: super(message)でThrowableに渡す(基本)

```java
class MyException extends Exception {
    public MyException(String message) {
        super(message);
    }
}
```

### 方法2: getMessage()自体をオーバーライド

```java
class MyException extends Exception {
    private int errorCode;
    public MyException(int errorCode) { this.errorCode = errorCode; }

    @Override
    public String getMessage() {
        return "エラーコード: " + errorCode;
    }
}
```

### throw new XXX("メッセージ") が使えるかの判定基準
そのクラスに**Stringを1つ受け取るコンストラクタ**が定義されているかどうかがすべて。

- 独自クラスで`super(message)`実装済み → OK
- 独自クラスにコンストラクタなし → コンパイルエラー
- 標準例外クラス(`IllegalArgumentException`など) → 最初から対応済みなのでそのまま使える

## 5. Map/Listのメソッド名

- **put**: `Map`系に実在(追加と更新を兼ねる。キーが存在すれば上書き)
- **update**: 主要コレクションには**存在しない**(引っかけ問題に注意)
- `List`の要素更新は`set`、`Map`の要素更新は`put`

| インターフェース | 追加 | 更新 | 削除 | 取得 |
|---|---|---|---|---|
| List | add | set | remove | get |
| Map | put | put | remove | get |
| Set | add | ― | remove | ― |

## 6. switch式のcaseラベル

`case`ラベルには**コンパイル時定数式**が必要(リテラル、または`final`かつコンパイル時に値が確定するもの)。

```java
final int A = 10;        // コンパイル時定数 → OK
final int B = getValue(); // 実行時に決まる → NG
final var C = 10;        // final + リテラル → OK
var D = 10;               // finalなし → NG
```

ポイントは「`var`だから使える」のではなく、「`final`が付いていて、かつ値がコンパイル時に確定するか」がすべて。

## 7. レコードクラスのメンバ

- レコードコンポーネント(宣言時の`(int x, int y)`)は自動的にフィールド化される
- それ以外の**追加のインスタンス変数**は宣言不可(コンパイルエラー)
- **static変数・staticメソッドは定義可能**
- **インスタンスメソッド(独自定義)、コンストラクタは定義可能**

```java
record Point(int x, int y) {
    int z;                          // NG: 追加のインスタンス変数
    static int count = 0;           // OK
    double distanceFromOrigin() {   // OK: 独自インスタンスメソッド
        return Math.sqrt(x * x + y * y);
    }
}
```

設計思想:レコードは「不変なデータの入れ物」であり、コンポーネント以外のフィールドを許すとこの保証が崩れるため制約がある。

## 8. インタフェースのstaticメソッド

インタフェースのstaticメソッドは実装クラスに**継承されない**。

```java
interface MyInterface {
    static void show() { System.out.println("static method"); }
}

class MyClass implements MyInterface {}

MyInterface.show(); // OK
MyClass.show();     // コンパイルエラー
obj.show();          // コンパイルエラー(インスタンス変数からもNG)
```

クラスのstaticメソッドは継承されて子クラス名から呼べるが、インタフェースのstaticメソッドは**インタフェース名からしか呼び出せない**。

| | staticメソッドの継承 | 呼び出し方法 |
|---|---|---|
| クラスの継承 | される | 親クラス名/子クラス名どちらでも可 |
| インタフェースの実装 | されない | インタフェース名のみ |
